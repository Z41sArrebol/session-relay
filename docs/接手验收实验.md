# 接手验收实验

> 2026-10-20。验证“失效会话 → 恢复简报 → 另一个 Agent 接手完成”这条链路是否真实成立。
> 产物目录：`docs/demo/handoff-experiment/`（含隔离会话的交接包与两阶段输出）。

## 实验设置

- 合成会话，使用真实 Z-Code schema（`session/message/part/todo/tool_usage/turn_usage/model_usage`）。
- 合成项目：一个登录骨架，`login()` 返回 `not implemented`；`login.test.ts` 已写好两个用例；会话里有一次 `npm test` 失败（退出码 1）且未解决；待办 1 项进行中、1 项待处理；无 AI 总结，只有确定性恢复简报。
- 接收方：Claude Code CLI（本机已安装）。连接器先跑无害自检（`RELAY_CONNECTOR_OK`），再进入两阶段。

## 结果

| 阶段 | 结果 | 证据 |
|---|---|---|
| 生成恢复简报 | 通过 | 简报可信度 medium（76 分），信号：工具失败 1 条、未完成待办、无收尾陈述 |
| 连接器自检 | 通过（4112 ms） | `RELAY_CONNECTOR_OK` |
| 独立验收 | 通过（46 s） | Agent 给出 BLOCKER + 3 条带证据路径的问题，全部指向包内文件 |
| 继续实现 | 通过（64 s） | Agent 只改 `login.ts`，未动 `login.test.ts` |
| 最终验证 | 通过 | `npm test` 退出码 0，2/2 用例通过 |

**判定 `ok: true`。** 接收方在没有 AI 总结、没有发送方补充的情况下，从恢复简报接手并完成了任务。

## 两个值得记录的细节

1. **接收方没有无条件相信“完成”**。实现阶段的 Agent 明确写：交接包里的 `npm test` 失败是历史记录，它实际运行时权限层拦截了 `npm`/`node`，所以“按测试逻辑静态核对应通过，但这不替代实际运行结果”。这与我们“执行者声称完成 ≠ 系统已验证”的约束一致。
2. **评审阶段拒绝得很准**。review 阶段判 BLOCKER，理由是：没有暂存/未暂存改动、交接证据里 `npm test` 退出码 1、没有收尾。它引用的是 `changes/`、`evidence/commands.md`、`session/excerpt.md`——也就是包里的确定性证据，不是猜测。

## 仍没解决的

- 这次用的是隔离合成任务，不是用户的真实工作。真实任务的约束更复杂（多文件、外部依赖、环境差异）。
- Z-Code 会话仍不能直接发送，需要复制粘贴；Claude 连接器要显式给 `SESSION_RELAY_CLAUDE_PATH`（nvm shim 不在 Windows 子进程 PATH 里）。
- 没有可安装包，实验目前跑在开发环境。
