## 4. 仍需手动完成的环节

1. **导出对话框**：文件夹/ZIP 写入逻辑已有测试，但系统原生保存对话框无法在无头 E2E 中自动点击；需要在桌面里手动选一次路径确认。
2. **真实模型总结**：用本地 mock 服务验证了请求、解析、引用核对与失败回退；没有用真实第三方模型 Key 跑过。需要在设置里填自己的兼容服务后点一次“测试连接”。
4. **Claude 连接器**：已实现自检（固定文本 `RELAY_CONNECTOR_OK`）与发送流程，但**没有执行真实往返**，因此保持“候选 · 未验证”。只有用户确认后跑通自检才会标记 verified。
5. **交给另一个 Z-Code 会话**：产品第一版只导出包 + 复制指令，需要用户到目标会话手动粘贴。Z-Code 没有公开外部发送入口，未做 UI 模拟或内部队列写入。
6. **AI 总结草稿的事实核对**：摘要里的 `[M:]/[T:]/[F:]/[C:]` 引用会做存在性检查，但引用内容是否被正确解释仍需接手者核对原始证据。

## 5. 结论

- “只读接入 + 增量采集 + Git 证据 + 打包 + 导出/复制指令”这条链路已在本机真实会话和隔离 E2E 中跑通。
- “完全不用用户操作的跨会话接力”没有打通，原因是 Z-Code 没有公开发送入口；界面明确降级，不冒充已发送。
- Claude CLI 只作为候选出口，不作为主路径；主路径仍是导出 + 粘贴。
